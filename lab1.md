# Лабораторная работа №1

**Тема:** Реализация конечного автомата для распознавания формальных языков  
**Индивидуальный вариант:** 15  
**Язык программирования:** Python

## 1. Цель работы

Изучить принцип работы детерминированного конечного автомата (ДКА), построить диаграмму переходов и реализовать программу, которая определяет принадлежность входного слова заданному формальному языку.

## 2. Постановка задачи

Вариант №15: **`(abcd)ⁿ(ef)ᵐ`, где n ≥ 1, m ≥ 1**.

Допустимое слово должно состоять из одного или нескольких подряд идущих блоков `abcd`, за которыми следует один или несколько блоков `ef`. Менять порядок блоков нельзя. Пустая строка не допускается.

Примеры правильных слов: `abcdef`, `abcdabcdef`, `abcdefef`, `abcdabcdefef`.

Примеры неправильных слов: `abcd`, `ef`, `abcef`, `abcdefabcd`, пустое слово.

## 3. Теоретические сведения и связь с лекциями

В лекции «Конечные автоматы» детерминированный конечный автомат (ДКА) описан как модель, которая считывает слово по одному символу и переходит из одного состояния в другое по заранее определённым правилам. После обработки всех символов слово принимается, только если автомат находится в допускающем состоянии.

В дополнительной презентации «§6. Конечные автоматы» конечный автомат (FSM) представлен как ориентированный граф: **вершины** обозначают состояния, а **дуги** — возможные переходы. В качестве примера приведены состояния игрового персонажа **WANDER** (бродить), **PURSUE** (преследовать), **ATTACK** (атаковать). Переходы зависят от событий, например появления противника в поле зрения.

Наш вариант использует тот же принцип «состояние + входное событие → следующее состояние», но вместо поведения NPC автомат распознаёт строку. Роль события выполняет очередной символ `a`, `b`, `c`, `d`, `e` или `f`. Таблица переходов ниже оформлена по тому же принципу, что таблица на странице 3 презентации: строки — текущие состояния, столбцы — входные события, ячейки — следующие состояния. В отличие от примера поведения NPC, у нас **ДКА**: для каждой пары «состояние, символ» определён ровно один переход, включая переходы в ошибочное состояние `qE`.

| Пример FSM для NPC (дополнительная теория) | ДКА для варианта 15 |
|---|---|
| Текущее состояние: WANDER / PURSUE / ATTACK | Текущее состояние: q0 … q6, qE |
| Событие: противник замечен | Входной символ: `a` … `f` |
| Изменение поведения NPC | Переход к следующей части шаблона |
| Обработка при обновлении игрового цикла | Обработка при чтении очередного символа |

## 4. Формальная модель автомата

Определим ДКА пятёркой **M = (Q, Σ, δ, q₀, F)**:

- **Q** = {q0, q1, q2, q3, q4, q5, q6, qE} — множество состояний.
- **Σ** = {a, b, c, d, e, f} — алфавит.
- **δ** — функция переходов из таблицы ниже.
- **q₀** = q0 — начальное состояние.
- **F** = {q6} — множество принимающих состояний.

Значения состояний:

| Состояние | Назначение |
|---|---|
| q0 | Начало чтения слова |
| q1 | Прочитан символ `a` текущего блока |
| q2 | Прочитано `ab` |
| q3 | Прочитано `abc` |
| q4 | Завершён как минимум один блок `abcd` |
| q5 | Прочитан `e` текущего блока `ef` |
| q6 | Завершён как минимум один блок `ef` (принимающее состояние) |
| qE | Ловушка: последовательность некорректна |

### Таблица переходов

| Состояние | a | b | c | d | e | f |
|---|---|---|---|---|---|---|
| q0 | q1 | qE | qE | qE | qE | qE |
| q1 | qE | q2 | qE | qE | qE | qE |
| q2 | qE | qE | q3 | qE | qE | qE |
| q3 | qE | qE | qE | q4 | qE | qE |
| q4 | q1 | qE | qE | qE | q5 | qE |
| q5 | qE | qE | qE | qE | qE | q6 |
| q6 | qE | qE | qE | qE | q5 | qE |
| qE | qE | qE | qE | qE | qE | qE |

**Примечание:** если пользователь введёт символ не из Σ, программа тоже переведёт автомат в qE.

## 6. Программная реализация

Программа содержится в файле **`automaton.py`**. В словаре `TRANSITIONS` перечислены корректные переходы. Если переход отсутствует, происходит переход в `qE`. Функция `recognize(word)` читает входную строку посимвольно и возвращает `True`, только если последнее состояние входит в множество `ACCEPTING_STATES`.

Реализация использует таблицу состояний и переходов, а не регулярное выражение, то есть непосредственно моделирует ДКА.

**Запуск:** `python automaton.py`. Сначала программа выполняет готовые тесты, затем предлагает вводить собственные слова. Чтобы выйти, нажмите Enter на пустой строке.

**Результат:** все 14 тестов прошли успешно.

### Пошаговая проверка слова `abcdef`

`q0 --a--> q1 --b--> q2 --c--> q3 --d--> q4 --e--> q5 --f--> q6`

Конечное состояние `q6` принадлежит F, поэтому слово принято.

### Пошаговая проверка слова `abcdefabcd`

После чтения `abcdef` достигнуто `q6`. Следующий символ `a` переводит автомат в `qE`, где он остаётся до конца слова. Слово отклонено.

## 8. Вывод

На основе двух лекций изучены представление автомата как графа состояний и описание переходов в табличном виде. В ходе лабораторной работы построен детерминированный конечный автомат, распознающий язык `(abcd)ⁿ(ef)ᵐ` при `n ≥ 1` и `m ≥ 1`. Разработаны таблица переходов, диаграммы состояний и программа на Python. Проверка на корректных и некорректных входных данных показала ожидаемые результаты. Автомат использует конечное число состояний и обрабатывает каждое входное слово за число шагов, равное длине строки.
